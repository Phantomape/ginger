任务 A — 新仓位：
- 先读第 4 节 new_trade_locked 字段。若为 true → "NO NEW TRADE"，跳至任务 B
- 从第 3a 节读取量化信号（已通过所有代码层门控）
- 若无信号 → "NO NEW TRADE"
- 检查第 2 节新闻：是否有 T1 负面新闻否决该信号？
  - 有 T1 负面 → "NO NEW TRADE"，在 veto_check 中说明具体新闻
  - 无 T1 负面 → 信号通过，生成交易（所有数值直接使用第 3a 节预计算值）
- 生成交易时必须 echo 第 3a 节的 strategy 字段（trend_long / breakout_long / earnings_event_long）

任务 A2 — 加仓动作：
- 读取第 3a-add 节 add-on actions（若存在）
- 这不是新开仓，不受 new_trade_locked 影响；它是代码层 follow-through 加仓
- 若无 T1 灾难新闻否决该 ticker → 原样输出到 add_on_trades
- 若有 T1 灾难新闻 → 不输出该加仓，并在 add_on_vetoes 写明新闻和理由

任务 B — 现有持仓审查（全部照搬代码决策）：
- 读第 4 节 position_states 和 suggested_reduce_pct
- CRITICAL_EXIT → EXIT，shares_to_sell = null，decision_mode = "forced_rule"
- TARGET_EXIT → EXIT，shares_to_sell = null，decision_mode = "forced_rule"
- ATR_EXIT → EXIT，shares_to_sell = null，decision_mode = "forced_rule"
- HIGH_REDUCE → REDUCE，shares_to_sell = 总股数 × suggested_reduce_pct / 100（向下取整），decision_mode = "forced_rule"
- HOLD → HOLD，shares_to_sell = null，decision_mode = "forced_rule"
- pending_unexecuted_actions overrides HOLD: repeat the prior REDUCE/EXIT with decision_mode = "pending_unexecuted_action"
- position_actions 必须包含所有持仓
