# Ginger v3 最小架构草案（2026-10-06）

状态：**草案，待用户确认**。本文不改变任何生产信号、交易权限或 V2 协议；V2 继续 `trade_enabled=false`。

## 0. 为什么要 v3

V2 的实际优化目标已经变成“产出合规、可审计的实验结论”：2710 条实验记录里 rejected 975、measurement repair 141，
LLM 大量时间花在数据管道和流程修复上；同时所有检验反复落在同一个约 50 只大盘股池和同一段历史上。
v3 的唯一目标：**一条扣全部成本后的组合净值曲线跑赢同资本 SPY 买入持有**，其余一切服务于它。

稳健性：
- 7 月一个月的超额就是 −$41.5k（BKSY、RKLB、PL、MRVL 等高 beta 名字集中下跌）。

- 结论：**合计没有正超额。个别 sleeve 为正，但样本都不到 30 笔；最好的情况是“扣成本后约等于 SPY”，最坏是集中暴露在高 beta 主题上的大回撤**。

### 1c. 北极星的定义（v3 起）

- **NS 指标**：v3 组合（先 paper、后实盘）扣全部成本后的**周度**净值，对比同资本 SPY 买入持有（股息再投资）。
- **主读数**：滚动 52 周超额收益和超额 Sharpe；**约束**：最大回撤不超过同期 SPY 回撤 + 5 pp。
- **起点**：上面的基线就是 v0 读数，即“目前系统 ≈ 每年跑输 SPY”。
- **朴素对照**：任何策略都必须同时跑赢 `SPY 200 日均线择时`（线上持有 SPY，线下持有 BIL）。连一行规则都跑不赢就不部署。

## 2. 组件（5 个，彼此单向依赖）

```
data/      确定性采集 + 健康检查（无 LLM）
  ↓
strategies/  每个策略一个纯函数：signal(prices[:t]) -> 目标权重；≤5 个参数，≤200 行  ← LLM 只能改这里
  ↓
evaluator/   冻结：回测引擎 + 成本模型 + 指标 + DSR + 试验登记       ← LLM 不可改、不可读 holdout
  ↓
portfolio/   固定规则：策略间按逆波动等风险合成，组合波动目标 10%，单资产上限 25%
  ↓
ledger/      试验登记（只追加）、paper NAV、实盘 NAV、NS 周报
```

- **全新的小仓库或子目录 `v3/`**，旧系统只读，不迁移任何 sleeve、名单、权重或收益结论。
- **数据**：
  - 起步宇宙是约 20 只跨资产 ETF：SPY QQQ IWM EFA EEM TLT IEF SHY GLD DBC VNQ HYG LQD UUP BIL，加主要行业 ETF。
  - 本地 warehouse 只有 2023-08 以后的数据（massive 只有 2024-07 以后），**必须先补长历史**：yfinance 从 ETF 成立日起的复权日线，落地一次后算哈希冻结。
  - 每日更新失败、行数异常或数据陈旧超过 1 个交易日，直接告警，不允许“status=ok 但没有数据”。
- **成本模型（冻结）**：ETF 每边 3 bp + 个股每边 10 bp + 每单 $1；通过门槛时必须在 2 倍成本下仍然成立。
- **订单策略标签**：实盘下单 remark 必须写 `v3:<strategy_id>:<config_hash>`，否则不计入 NS。这是 1a 里“无法归因”的直接修复。

## 3. 评估器冻结方式

1. **代码冻结**：
   - `evaluator/` 加上成本模型和数据 manifest，生成 `evaluator.lock`（逐文件 SHA256）。每次评估先校验哈希，不一致就拒绝运行。
   - 修改 evaluator 只能由用户手工提交；提交信息里带 `evaluator-change-approved-by-user`，pre-commit hook 检查这一点。
2. **LLM 写权限隔离**：定时任务的 `.claude/settings.json` 设置
   `permissions.deny: ["Edit(v3/evaluator/**)", "Write(v3/evaluator/**)", "Edit(v3/portfolio/**)", "Read(v3/data/holdout/**)"]`。
   Bash 仍然可以绕过这一层，所以它只是第一道防线，真正的隔离靠第 3 条。
3. **Holdout 物理隔离**：
   - holdout 区间的价格文件和 holdout 评估都放在**另一个 Windows 用户账户**下，用 NTFS ACL 禁止当前用户读取，由该用户的计划任务运行。也可以放到云端 routine。
   - LLM 只能拿到 `pass / fail / 年化超额（四舍五入到 0.5%）`，拿不到净值曲线和逐笔结果。
4. **时间切分**（补齐长历史后）：

| 区段 | 区间 | 谁能看 | 用途 |
|---|---|---|---|
| Dev | 数据起点 → 2016-12-31 | LLM 随意用 | 开发、调参 |
| Validation | 2017-01-01 → 2021-12-31 | 只能通过 `evaluator submit`，每次计 1 次试验 | 筛选 |
| Holdout | 2022-01-01 → 2026-06-30 | 隔离账户，按季度批量 | 最后一道过滤 |
| Forward | 2026-07-01 之后 | paper → 实盘 | **唯一的真证据** |

5. **一个绕不开的事实**：LLM 的训练知识覆盖到 2026-06，它“知道” 2008、2020、2022 年发生过什么，所以任何历史 holdout 都已经被它的先验污染。
   历史区段只能用来**淘汰**策略，不能用来**证明**策略。晋级必须靠 forward。这也是 holdout 截在 2026-06-30 的原因。

## 4. 试验预算规则

- **一次试验** = 一个不同的 `config_hash` 在 validation 上提交一次。在 dev 上的回测不限次数，但 evaluator 会自动记录次数，周报里如实显示。
- **预算**：每季度 **12 次** validation 提交，用不完不结转；holdout 每季度一批，**最多 3 个**候选。
- **终身计数器不清零**：DSR 用的 N = 历史累计 validation 提交数，换名字或换 ID 都不重置。失败策略的变体（同一族、只改参数）每次计 **2** 次。
- **Validation 通过条件**（全部满足）：
  1. 扣成本后年化 Sharpe ≥ 0.5，且在 2 倍成本下仍 ≥ 0.3；
  2. DSR 概率 ≥ 0.95（N 用终身累计）；
  3. 跑赢 SPY 和 200 日均线择时这两个朴素对照；
  4. 最大回撤 ≤ 25%；
  5. 加入现有组合后，组合 Sharpe 提高（同资本替换）。
- **Holdout 通过条件**：超额方向与 validation 一致，且扣成本 Sharpe ≥ 0.3。没过就记入族谱，不允许改完再交同一窗口。
- **Forward 晋级**：paper 满 3 个月且实现 Sharpe 不低于 validation 的 −2σ，之后实盘从 10% 资金开始，每季度最多加一档。
- **撤销**：forward 滚动 6 个月超额低于预期 −2σ 就减半；连续两次触发就移出组合。

## 5. LLM 的角色和节奏

- **研究：每周一次**，不是每小时。每次只做一件事：写或改 `strategies/` 下的一个文件，在 dev 上回测，决定是否消耗预算提交。
- **运维：确定性 cron，不用 LLM**。只有告警触发时，才派一个有边界的修复任务，修完即止。
- **周报只放三样东西**：NS 曲线对比 SPY、已用和剩余预算、组合构成。不统计实验数、ticket 数和 receipt 数，避免再奖励“流程产出”。
- **先验**：优先测有几十年跨市场证据的风险溢价，不再追新奇另类数据。初始候选：
  1. 跨资产时序动量 / 趋势
  2. 行业 ETF 横截面动量
  3. 低波动倾斜
  4. 债券 carry / 期限
  5. 波动率目标本身

  另类数据只有在“组合里已经有正 NS”之后，才作为增量候选。

## 6. 落地顺序（每步都有验收）

1. 补长历史 ETF 日线并冻结哈希。验收：SPY 从 1993 起、其余 ETF 从成立日起，manifest 可复现。
2. 写 evaluator 和成本模型，加 4 个合成数据单测（常数价格 → 0 收益；已知趋势 → 已知方向；缺失值；拆股）。验收：测试通过，lock 文件生成。
3. 实现 S0（SPY）、S1（200 日均线择时）两个对照，跑出 dev 和 validation 读数。验收：与手算对得上。
4. 搭 holdout 隔离账户和 permissions deny。验收：LLM 账户读 holdout 文件被拒绝。
5. 每周的 LLM 研究循环开始消耗预算；NS 周报上线。
6. 第一个通过 holdout 的组合进入 paper；实盘下单 remark 带 v3 标签。

**停止条件**：如果 4 个季度（约 48 次提交）后仍然没有组合跑赢 200 日均线择时，结论就是“在这个数据和成本条件下没有可交易的超额”。
这时把资金放进朴素对照，研究降为每季度一次。这是一个合法的、能省钱的结果。
