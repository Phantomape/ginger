# Ginger v3 最小架构（2026-10-06 起草，10-07 用户确认）

状态：**已确认（用户 2026-10-07）**，已并入 [10-06 评审](v3_iteration_review_20261006.md) 的修改。
本文不改变任何现有生产信号或交易权限；V2 继续 `trade_enabled=false`，V3 实盘下单仍需用户逐次授权（第 6 节第 6 步）。

## 0. 为什么要 v3

V2 的实际优化目标已经变成“产出合规、可审计的实验结论”：2710 条实验记录里 rejected 975、measurement repair 141，
LLM 大量时间花在数据管道和流程修复上；同时所有检验反复落在同一个约 50 只大盘股池和同一段历史上。
v3 的唯一目标：**一条扣全部成本后的组合净值曲线跑赢同资本 SPY 买入持有**，其余一切服务于它。

### 1b. Paper sleeve 合计（`data/paper_sleeves/*/state.json`）

26 个有平仓记录的 sleeve，共 346 笔，平仓日 2026-05-12 → 09-25。每笔都有同名义、同持有窗口的 SPY 对照（`replacement_value_vs_spy_usd`）。

| 指标 | 值 |
|---|--:|
| 已实现盈亏（记录口径，已含 0.35% 往返成本 + 滑点） | **−$41,788** |
| 同资金同窗口买 SPY 的盈亏 | −$3,406（含同样的成本） |
| 相对 SPY 超额 | **−$38,382**；相对 QQQ −$31,793 |
| 每笔平均超额 / t 值 | −1.84% / **−3.0** |
| 胜率 | 45% |
| 超额为正的 sleeve | 13 / 26（全部 < 30 笔，10 个 ≤ 10 笔） |
| 估算成本拖累 | ≈ $18.7k（名义 $4.15M × 0.45%） |

稳健性：
- 7 月一个月的超额就是 −$41.5k（BKSY、RKLB、PL、MRVL 等高 beta 名字集中下跌）。
- 剔除 7 月后每笔平均超额 −0.22%（t = −0.33）；只看 8–9 月是 −0.35%（t = −0.44）。
- 结论：**合计没有正超额。个别 sleeve 为正，但样本都不到 30 笔；最好的情况是“扣成本后约等于 SPY”，最坏是集中暴露在高 beta 主题上的大回撤**。
- 各 sleeve 是独立账本，持仓互相重叠（例如 COIN、NOW 在同一个 sleeve 里各出现两次），所以这不是单一组合的净值，t 值偏高估。方向仍然清楚。

### 1c. 北极星的定义（v3 起）

- **资本**：V3 名义资本 **$100,000**（用户 2026-10-07 指定）。所有 NS 对照都按同资本计算。
- **NS 指标**：V3 组合（先 paper、后实盘）扣全部成本后的**周度**净值，对比**波动匹配的 SPY**
  （SPY + BIL 混合，使其过去 52 周已实现波动等于组合），股息再投资。原始 SPY 买入持有作为参考读数一起报告。
- **主读数**：滚动 52 周超额收益和超额 Sharpe；**约束**：最大回撤不超过同期波动匹配 SPY 回撤 + 5 pp。
- **起点**：上面的基线就是 v0 读数，即“目前系统 ≈ 每年跑输 SPY”。
- **朴素对照**（同样波动匹配）：S0 SPY、S1 `SPY 200 日均线择时`（线上持有 SPY，线下持有 BIL）、S2 波动匹配 SPY。
  连一行规则都跑不赢就不部署。
- **比较对象永远是固定的外部对照**，不能是当前在位的组合（V1 用自己的股票组合做 Gate 4 基准，结构上拒绝一切不像它的东西，见评审 7.1）。

## 2. 组件（5 个，彼此单向依赖）

```
data/      确定性采集 + 健康检查（无 LLM）
  ↓
strategies/  每个策略一个纯函数：signal(prices[:t]) -> 目标权重；≤5 个参数，≤200 行  ← LLM 只能改这里
  ↓
evaluator/   冻结：回测引擎 + 成本模型 + 指标 + DSR + 试验登记       ← LLM 不可改
  ↓
portfolio/   固定规则：策略间按逆波动等风险合成，组合波动目标 10%，单资产上限 25%
  ↓
ledger/      试验登记（只追加）、paper NAV、实盘 NAV、NS 周报（快照只追加不覆盖）
```

- **新子目录 `v3/`**，旧系统只读，不迁移任何 sleeve、名单、权重或收益结论。
  V1 里测过的 5 张趋势/跨资产票（评审 7.1）登记进 V3 族谱，标记“在错误基准下看过”，既不当负面先验，也不当新发现。
- **数据分两层**：
  - **证据层**（用来判定有没有超额）：Ken French 行业/因子组合（1926 起，月频）、FRED 利率曲线、各国股指长序列。
  - **交易层**（用来核对成本、实现、可交易性）：约 20 只跨资产 ETF：SPY QQQ IWM EFA EEM TLT IEF SHY GLD DBC VNQ HYG LQD UUP BIL，加主要行业 ETF；
    yfinance 从成立日起的复权日线（只在 `.venv` 里有 yfinance）。
  - 两层都落地一次后算哈希冻结，manifest 可复现。
- **只用可回补的数据（2026-10-08 用户要求：研究不应依赖电脑天天开着）**：
  - V3 的每个输入都必须能在任何时候从公开源**重新下载完整历史**（yfinance/Stooq 复权日线、Ken French、FRED、券商导出的对账单）。
    不使用“只有当天抓才有、错过就永久缺失”的快照型数据（盘中快照、借券、资金流、新闻观察者、forward observer 账本）。
  - 数据脚本是**追赶式**的：每次运行比较本地最后日期与最新交易日，一次补齐中间所有缺口；关机一周后开机跑一次即可恢复，没有数据断档。
  - 数据更新在每周研究任务开头由确定性脚本完成，**不需要每天运行的定时任务**，也不需要 LLM。
  - 将来如果确实要用快照型数据（只能是 B 类候选），采集必须放到云端（如 GitHub Actions cron），不能依赖本机。
- **数据健康**：用 `now − generated_at` 与预期频率判断新旧，**不读上一次运行留下的 status 字段**。
  补齐后仍缺数据或行数异常 → 告警放在 NS 周报第一行，且该周 NS 不出数（不出旧数）。
- **成本模型（冻结）**：ETF 每边 3 bp + 个股每边 10 bp + 每单 $1；通过门槛时必须在 2 倍成本下仍然成立。
- **券商与归因**：2026-10-08 起用户改用 **Robinhood**（moomoo 账户已清空，第 1a 节为历史读数）。Robinhood 没有官方股票交易 API，也没有订单 remark，所以：
  - V3 用**专门的账户**（只放 V3 资金、只做 V3 订单），账户层面即可归因，不再依赖 remark；
  - 下单由用户手工执行（V3 是周/月频，单量小）；系统每周输出目标权重和订单清单；
  - 实盘 NAV 来自用户导出的 Robinhood 对账单/交易记录 CSV（可回补），不跑本地券商采集；不使用非官方 API，不保存券商密码。

## 3. 评估器冻结方式

1. **代码冻结**：
   - `evaluator/` 加上成本模型和数据 manifest，生成 `evaluator.lock`（逐文件 SHA256）。每次评估先校验哈希，不一致就拒绝运行。
   - evaluator 拒绝在 dirty tree 上 submit。
   - 修改 evaluator 只能由用户手工提交；提交信息里带 `evaluator-change-approved-by-user`，pre-commit hook 检查这一点。
2. **LLM 写权限**：定时任务的 `.claude/settings.json` 设置 `permissions.deny: ["Edit(v3/evaluator/**)", "Write(v3/evaluator/**)", "Edit(v3/portfolio/**)"]`。
   Bash 可以绕过，所以真正的防线是 lock 校验 + pre-commit hook。
3. **不建隔离 holdout 账户**：LLM 的训练知识覆盖到 2026-06，任何历史区段都已被它的先验污染，只能用来**淘汰**策略。
   隔离账户成本高、收益低；改用“证据层长历史 + forward 实现核对”（第 4 节）。
4. **时间切分**（证据层与交易层同用）：

| 区段 | 区间 | 用途 |
|---|---|---|
| Dev | 数据起点 → 2016-12-31 | 开发、实现核对；不限次数，evaluator 自动计数 |
| Validation | 2017-01-01 → 2026-06-30 | 只能通过 `evaluator submit`，每次计 1 次试验 |
| Forward | 2026-07-01 之后 | paper → 实盘；**验证实现一致性**，不用短期收益判晋级 |

## 4. 试验与晋级规则

- **两类候选，分别计数**：
  - **A 类“文献规定型”**：规则和参数在原始论文里写死（例如 12 个月时序动量、Faber 10 个月均线、行业 12-1 动量、低波动倾斜、债券 carry），
    LLM 只负责忠实实现，**不调参**。多重检验 N = A 类候选总数（个位数）。在证据层全历史上一次性评估，结果全部登记（包括失败）。
  - **B 类“LLM 新造型”**：每季度 **12 次** validation 提交，用不完不结转；DSR 的 N = B 类终身累计提交数，换名字或换 ID 不重置；
    同族只改参数的变体每次计 2 次。**只有 A 类组合已经在 forward 上 NS 不为负之后才开放。**
- **门槛可达性先行**：任何数值门槛写进 evaluator 前，先算出“典型候选 Sharpe 在该样本长度和 N 下能否通过”的表（评审第 1 节）；
  不可达的门槛不得上线。参考：5 年窗即使 N=1 也需年化 Sharpe ≥ 0.74；50 年证据层 PSR>0 只需 ≥ 0.23。
- **通过条件**（全部满足）：
  1. 证据层：扣成本后 PSR（A 类）或 DSR（B 类）≥ 0.95；
  2. 交易层：扣成本后年化 Sharpe ≥ 0.3，且 2 倍成本下仍为正；
  3. 跑赢 S0/S1/S2（波动匹配口径）；
  4. 最大回撤 ≤ 25%；
  5. 加入现有 V3 组合后组合 Sharpe 提高（同资本替换）。
- **Forward 晋级**：paper 满 3 个月，且 paper 净值与冻结 evaluator 同期回放的跟踪误差年化 < 1%、换手和成本与模型一致。
  3 个月收益**不**作为晋级依据（统计功效不足：IR 0.5 需约 16 年到 t=2）。
- **实盘规模**：从 $100k 的 10%（$10k）起步，每季度最多加一档（10% → 25% → 50% → 100%），每档需用户确认。
- **撤销**：forward 滚动 12 个月波动匹配超额低于预期 −2σ 就减半；连续两次触发就移出组合。实现跟踪误差超限立即停单排查。

## 5. LLM 的角色和节奏

- **研究：每周一次**。每次只做一件事，按第 6 节落地顺序推进下一步，验收通过才进入下一步。
- **只允许一个 writer**：V3 研究任务是 `v3/` 唯一写入方。旧的 V2 研究与维护循环（Codex `Edge V2` 每小时、`Chore`）已于 2026-10-07 暂停。
- **运维：不需要每日任务**。数据在每周研究任务开头追赶式补齐（第 2 节）；只有补齐失败时，才派一个有边界的修复任务，修完即止。
- **周报只放三样东西**：NS 曲线对比波动匹配 SPY、已用和剩余预算、组合构成（数据告警在第一行）。不统计实验数、ticket 数和 receipt 数。
- **先验**：优先测有几十年跨市场证据的风险溢价（A 类），不追新奇另类数据。另类数据只有在“组合里已经有正 NS”之后，才作为 B 类增量候选。

## 6. 落地顺序（每步都有验收）

1. 证据层 + 交易层数据落地并哈希冻结。验收：SPY 从 1993 起、其余 ETF 从成立日起、Ken French/FRED 全历史，manifest 可复现；健康检查按新旧判断；删掉最近 10 天数据后重跑能原样补回（追赶式验收）。
2. evaluator + 成本模型 + 合成数据单测（常数价格 → 0 收益；已知趋势 → 已知方向；缺失值；拆股；现金不能为负、权重和 ≤ 1）+ 门槛可达性表 + lock。验收：测试通过，lock 生成。
3. 对照组 S0、S1、S2，dev 读数与手算对得上。
4. A 类候选（不调参）在证据层全历史一次性评估，结果全部登记。
5. 通过的 A 类候选按固定规则合成组合 → paper（$100k 名义），同时跑实现一致性核对。
6. 用户确认后，专门的 Robinhood 账户、$10k 起步，用户按周度订单清单手工下单，NAV 用导出的对账单核对。B 类研究此后才开放。

**停止条件**：4 个季度后仍没有组合跑赢波动匹配的 S1，结论就是“在这个数据和成本条件下没有可交易的超额”。
这时把资金放进朴素对照，研究降为每季度一次。这是一个合法的、能省钱的结果。
