# Experiment Card: exp-20260922-007

## Summary

The candidate_decision_training_ledger append path keys idempotency on observation_id, whose identity includes intraday-varying price fields (entry/stop/target), so a second run.py pass on the same decision day (the 2026-09-21 18:13Z mid-session pass followed by the 03:06Z nightly pass) appended a second candidate_decision_snapshot for the same (as_of, ticker) planned entry (META as_of 2026-09-21 -> entry 2026-09-22 persisted twice under different observation_ids); the Form4 sale-overhang forward consumer then mints one decision per observation_id and counts every closed aggregate row toward the frozen 25-closed-decision reopen bar, so duplicate rows of one economic decision (same ticker, same entry session; also the weekend re-selections DE 2026-08-24 and RTX 2026-07-27) inflate the count: 7 persisted decision rows are 5 economic decisions. Repair, forward-only: (a) append skips a snapshot row whose (as_of, ticker) already exists in the ledger or earlier in the same batch and records rows_skipped_same_day_economic_duplicate in state; (b) summarize_forward_reopen_progress collapses closed rows to one per (ticker, entry_date) before every gate count and share, reporting the raw record count and the excluded duplicates for monitoring. Acceptance is correct implementation of the frozen decision identity verified by synthetic unit tests plus an outcome-blind identity projection over the persisted ledgers; no persisted row is rewritten or re-keyed; no outcome field is read; it is not judged by any count moving toward or away from the bar.
