- `scripts/build_reopen_readiness.py` counted those raw ok tags, so the
  `short_volume_q5_soft_tilt` lane flipped to a **false ready (20/20, 0.35)**
  on the morning of 2026-08-13 — the reverse-false-ready shape of the
  2026-08-04 prediction-market case. The concurrent codex zero-ID report
  (2026-08-11/13, `alpha_automation_q5_readiness_preflight_20260811.json`)
  first flagged the honest-PIT gap; this ticket machine-verified and fixed it.

## The single attributable repair bundle

1. **`quant/moomoo_daily_short_volume_archive.py`** (new): incremental daily
   refresher. Data-calendar anchored (per-ticker archive max activity_date;
   wall clock never enters row identity), append-only (existing rows keep their
   original `collected_at` vintage), atomic rewrite only when new rows exist,
   bounded TCP preflight (the moomoo SDK constructor blocks in an unbounded
   reconnect loop on a dead port — found live by this ticket's boundary smoke
   test), explicit non-ok statuses.
2. **`quant/forward_replacement_value.py`** tag rule v2: fail-closed
   `stale_archive` when the as-of source activity date is >5 calendar days
   before entry (percentile withheld); new audit fields
   `entry_short_volume_source_activity_date / _source_collected_at /
   _staleness_days / _vintage` (collected_before_entry vs
   collected_after_entry); stale rows re-tag on later runs.
3. **`quant/run.py`**: refresh wired producer-before-consumer ahead of
   `enrich_all_sleeve_states`; summary exposed as
   `short_volume_archive_refresh_summary` in trend signals.
4. **`scripts/build_reopen_readiness.py`** lane rebind: `q5_settled` now counts
   ONLY status ok AND vintage collected_before_entry (full honest contract per
   the 2026-08-04 rule); raw any-vintage and stale counts reported for
   visibility.
