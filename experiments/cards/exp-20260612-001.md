## Post-Run Reflection

- Why did the result happen? The daily run executes every calendar day while the
  latest downloadable bar is the prior session's; eight older sleeves keyed hold
  aging and pending fills on the run date, so weekends/holidays aged holds with
  stale Friday bars and booked phantom same-day rows. A pure calendar-rule
  session test (`quant/us_market_calendar.py`) fixes all eight without plumbing
  market data into their state machines.
- Which near-neighbor retry is now forbidden? Re-introducing run-date-keyed
  advancement/fills; hand-editing sleeve closed rows outside an archived,
  experiment-logged quarantine.
- What new evidence would justify a retry? A special NYSE closure (not covered
  by holiday rules) producing a phantom row; then add an explicit special-closure
  set plus tests.
