## Summary

## Post-Run Reflection

- Why did the result happen? The empty-only fetch condition made the first
  successful archive write permanent, so daily runs always took the
  local_archive branch and both archives froze. Staleness thresholds above each
  publisher's normal lag (FTD 21d, FINRA 16d) re-open the fetch path exactly
  when a newer file should exist; the zip/csv source caches keep retries cheap.
- Interesting calibration note: the FTD staleness turned out to be mostly real
  SEC publication lag (the May second-half file is still 404), so that archive
  was already as current as the publisher allows; FINRA was genuinely behind
  and gained two settlements (527 -> 580 rows, newest 2026-04-30 -> 2026-05-15).
- Forbidden near-neighbor retry: tightening thresholds below publisher lag to
  force daily fetches; switching the merge to overwrite-all (would let vendor
  restatements rewrite PIT history).
