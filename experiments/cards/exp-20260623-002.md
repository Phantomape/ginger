For chop-negative sleeves, `choppy_range` is the ONLY losing bucket while
`risk_on_trend` and `risk_off_stress` stay strongly positive (FGRS signature).
`industry_stable_core_flow` tracks the core stack (chop is its best bucket)
because it only admits candidates with same-day core entry flow.

**Scope set (chop down-tilt should cover):** fiftytwo_week_high_proximity,
supplier_financing_debt_relief, sbc_burden_improvement,
turn_of_month_liquid_leadership (+ FGRS); distribution_day_absorption borderline.
**Exclude set:** industry_stable_core_flow, narrow_range_compression_breakout
(only 2 chop trades), revision_surprise (0 chop trades), and the core stack.

## Post-Run Reflection

- Why did the result happen? Standalone candidate-pool sleeves enter freely in
  any regime and their momentum/quality edge degrades in directionless chop;
  the core stack and the core-flow-gated sleeve concentrate entries in trend
  regimes by construction, so they do not carry the chop-loss.
- Which near-neighbor retry is now forbidden? Re-slicing these frozen windows
  with different regime labels/thresholds, or tuning the exposure floor /
  regime constants. The frozen-window counterfactual tilt only shrinks PnL on
  net-positive windows; it is not acceptance evidence.
- What new evidence would justify a retry? Forward / live-pilot rows tagged with
  entry-time regime (via `quant/regime_tagged_scorecard.py`) that contain
  genuinely loss-making chop trades, then a separate Gate 1-4 applying the soft
  `exposure_scalar` down-tilt ONLY to the scope-set sleeves.
