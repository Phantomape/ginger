# Experiment Card: exp-20260727-004

## Summary

The live position-control ledger blocker report_open_positions_asof_mismatch is a semantic-relevance defect: it compares report_date to positions_as_of with strict string equality, but moomoo_open_positions stamps as_of with the UTC calendar date, so every normal post-close Pacific-evening run produces positions_as_of = report_date + 1 and the blocker has fired 100% of days since the ledger's first day (2026-07-07), making ok_to_add_control_pass permanently false and zero-information. The check should be ordering-based: block only when positions_as_of is OLDER than report_date (true staleness, e.g. the 2026-07-26 broker-refresh outage which must remain blocked), not when the snapshot is fresher than the report.
