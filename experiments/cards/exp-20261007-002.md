# Experiment Card: exp-20261007-002

## Summary

Measurement repair of the news-propagation pair paper sleeve settlement (exp-20260827-001 contract, exp-20260913-007 grace rule): settle_pair_basket measures the 5-session unsettleable grace period on the SPY session-anchor calendar, which the 56-ticker core primary_batch refreshes first in every run.py pass, instead of on the authorized price sources own coverage. After the 2026-09-26..10-06 machine outage the catch-up pass settled the sleeve at 2026-10-07T00:56:01Z while massive_history daily_bars still ended 2026-09-24 (grouped:2026-09-25 checkpoint completed 00:56:40Z, 39 seconds later) and the anchor already reached 2026-10-06, so the first acceptance-countable basket news-first-seen-39644ff3bf36cb2bdb66 (entry 09-14, exit 09-25, short legs AIOT and INSG priced only by massive, admission priceability passed on 09-04..09-11) was terminalized unsettleable although its exit bars exist. Read-only replay: with massive pruned to 09-24 the current code returns unsettleable (bug reproduced); with today full bars the same frozen decision returns outcome_status settled (status only read). Fix: load_pair_bars records __source_last_sessions__ (anchor last session and massive MAX trade_date); settle_pair_basket terminalizes a missing leg as unsettleable only when the anchor calendar AND the massive source have both reached the grace session calendar[exit_index+5], otherwise it keeps the ordinary missing_leg_bars blocker; bars mappings without the key keep the legacy anchor-only behaviour. Forward-only: the false unsettleable row for basket 39644ff3 is NOT rewritten or re-settled under this ID (append-only ledger, user decision).
