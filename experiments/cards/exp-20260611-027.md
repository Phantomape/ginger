## Post-Run Reflection

- Why did the result happen? git keeps only pointers in the index for LFS paths;
  a checkout-like operation on 2026-06-05 rewrote 51 worktree files without the
  smudge step while every object stayed in `.git/lfs/objects`, so restoration was
  offline and lossless. The coverage manifest was a two-layer pointer/append
  hybrid; the full 522-row history was recovered from the inner object and merged
  with the 14 appended rows (536 rows, 20241002-20260610, no gap).
- Which near-neighbor retry is now forbidden? Re-adding broad LFS patterns
  (data/non_ohlcv/**, docs/experiment_log.jsonl) without a materialization guard;
  bypassing quant/test_no_lfs_pointer_data_files.py.
- What new evidence would justify a retry? The guard test firing again, with
  reflog/process attribution captured before restoring.
